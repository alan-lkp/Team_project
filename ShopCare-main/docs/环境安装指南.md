# ShopCare 环境安装指南

本指南面向**从零开始把这套系统跑起来**的人, 覆盖四件事:

1. 装 Python 环境(服务侧 + 你打算用的模型侧);
2. 起 MySQL / Redis(可选, 连不上会自动降级);
3. 放置本地 BERT 预训练模型(**本项目不联网下载**);
4. 用自检脚本确认"我这一台机器到底能跑到哪一步"。

> 如果你的机器上已经有别的项目在跑, 建议**单独建一个 conda 环境**, 不要复用。
> 原因见文末「常见问题」里的 `config.py` 同名冲突一节。

---

## 一、技术栈总览

这个项目横跨四个技术栈, 依赖是**分层叠加**的, 没必要一次全装:

| 层次 | 目录 | 关键技术 | 必需性 |
|---|---|---|---|
| 服务层 | `backend/`, `frontend/` | FastAPI + Uvicorn + PyJWT + PyMySQL + redis | **必需**, 少了跑不起接口 |
| 对照组 1 | `02-rf/` | scikit-learn(TF-IDF + OneVsRest 随机森林) | 按需 |
| 对照组 2 | `03-fasttext/` | fasttext(多标签 `loss=ova`) + jieba | 按需 |
| 对照组 3 | `04-bert/` | torch + transformers(BERT + 手写 LoRA) | 按需, 且需自备预训练权重 |
| 工具与业务 | `tools/`, `08`~`11` | 纯标准库 + 上面几个的复用 | 跟随 |

**只想看页面和接口**: 只装「服务层」就够, 模型不可用时后端会明确降级并说明原因。

## 二、Python 环境

### 2.1 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Python | **3.11**(推荐) / 3.9~3.12 | 本项目在 3.11.16 上实测通过 |
| 操作系统 | Windows / Linux / macOS | 全部脚本无平台特定依赖 |
| 内存 | 8 GB 起 | 跑 BERT 训练建议 16 GB |
| 显卡 | 非必需 | `04-bert/config.py` 会自动选 cuda / mps / cpu |

> **Python 3.13 暂不推荐**: `fasttext` 与 `torch` 的预编译 wheel 在 3.13 上还不齐,
> 装起来多半要自己编译。用 3.11 最省事。

### 2.2 创建环境

```bash
conda create -n PYTHON_NLP python=3.11 -y
conda activate PYTHON_NLP
```

### 2.3 安装服务层依赖(必需)

```bash
pip install -r backend/requirements.txt
```

`backend/requirements.txt` 里**默认只启用服务必需的那 6 个包**, 模型侧的包是注释掉的 ——
这样最小部署不会被迫装几百 MB 的 torch。装完这 6 个, `/health`、页面、登录、工单 CRUD、
看板全部可用(模型推理会走降级)。

### 2.4 按需安装模型侧依赖

```bash
# 对照组 1: 随机森林
pip install numpy scikit-learn scipy joblib

# 对照组 2: FastText
pip install fasttext jieba

# 对照组 3: BERT(CPU 版; CUDA 见 2.5)
pip install torch transformers

# 数据分析(01-data/data_eda.py)与工具脚本用到
pip install pandas
```

### 2.5 CUDA(GPU)可选

```bash
pip install torch --index-url https://download.pytorch.org/whl/cu121
```

装完确认:

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

`True` 即可用 GPU; 训练脚本会自动挑设备, 不需要改代码。**显存不足**时把
`04-bert/config.py` 里的 `batch_size` 从 32 降到 16 / 8 / 4。

## 三、MySQL 与 Redis(都可以不装)

### 3.1 不装会怎样

**后端会自动降级, 接口与页面照常可用**:

| 组件 | 不可用时退化为 | 后果 |
|---|---|---|
| MySQL | 进程内 `MemoryStore` | 数据重启即丢; `/health` 显示 `storage_mode: memory` |
| Redis | 进程内限流 + 进程内缓存 | 多 worker 不共享计数; 缓存不跨进程 |

降级信息会**明确暴露在 `/health` 与页面「系统状态」页**, 不会静默替换 —— 这是本项目的
设计原则: 能降级, 但必须让你看见。

### 3.2 起 MySQL

```bash
# 1) 建库建表(推荐: 直接执行仓库里的 schema)
mysql -u root -p < backend/schema.sql

# 或者: 让后端启动时自动建(默认开启 DB_AUTO_CREATE=true)
#    需要账号有 CREATE DATABASE 权限; 没有就改成 false
```

`schema.sql` 会建 4 张表: `users`(账号)、`tickets`(工单及决策快照)、
`reviews`(人工复核记录)、`audit_logs`(审计日志)。

### 3.3 起 Redis

Redis 在本项目只承担三件事, 全都有进程内兜底, 所以**本地开发完全可以不开**:

| Key 模式 | 用途 | TTL |
|---|---|---|
| `shopcare:ratelimit:{身份}:{窗口}` | 固定窗口限流 | 60 s |
| `shopcare:cache:classify:{md5(...)}` | 分类结果缓存 | 60 s |
| `shopcare:jwt:blacklist:{jti}` | 登出令牌黑名单 | 令牌剩余有效期 |

> 注意第三项的语义: **登出黑名单在 Redis 不可用时只在进程内生效**, 重启后失效。
> 生产环境请务必让 Redis 可用, 否则登出的 token 在过期前理论上还能用。

### 3.4 配置连接信息(环境变量)

**本项目一律走环境变量, 不在代码里写死任何主机/账号**。把 `backend/.env.example`
复制成 `backend/.env`, 再按实际情况改:

```bash
cp backend/.env.example backend/.env
```

`backend/main.py` 启动时会自动读这个文件(**已存在的真实环境变量优先**, 不会被覆盖),
你也可以不用 `.env` 直接 `export` / `set`。

关键变量一览(完整列表见 `backend/.env.example` 里的注释):

| 变量 | 默认 | 说明 |
|---|---|---|
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | `127.0.0.1` / `3306` / `root` / 空 / `shopcare` | MySQL 连接 |
| `DB_AUTO_CREATE` | `true` | 启动时自动执行 `schema.sql` |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_DB` / `REDIS_PASSWORD` | `127.0.0.1` / `6379` / `0` / 空 | Redis 连接 |
| `JWT_SECRET` | `dev-secret-change-me` | **生产必须替换** |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | `admin` / `admin123` | 首次启动自动创建管理员 |
| `MODEL_AVAILABLE` | `rf,fasttext,bert` | 页面下拉框里出现哪些模型 |
| `DEFAULT_MODEL` | `bert` | 「自动」模式下先用哪个 |
| `ENABLE_LLM_FALLBACK` | `false` | 是否允许 LLM 兜底(会产生 API 费用) |
| `LABEL_THRESHOLD` / `GLOBAL_THRESHOLD` | `0.5` / `0.8` | 双阈值拒识 |

`JWT_SECRET` 生成方式:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

## 四、BERT 预训练模型(**必须自备, 本项目不联网下载**)

`02-rf` / `03-fasttext` 的模型产物仓库里已经带好了(或可用 `tools/generate_ticket_data.py`
+ 训练脚本重新生成), 但 `04-bert` 需要一个**本地的 `bert-base-chinese` 目录**。

### 4.1 放置位置

默认路径是 `04-bert/bert-base-chinese/`, 目录里至少要有:

```
04-bert/bert-base-chinese/
├── config.json              # 必需
├── vocab.txt                # 必需(tokenizer)
├── tokenizer_config.json
└── pytorch_model.bin        # 或 model.safetensors, 二选一
```

### 4.2 换到别的位置

用环境变量指过去即可(比如你已经有一份 RoBERTa 想替换):

```bash
set BERT_MODEL_DIR=D:\models\bert-base-chinese        # Windows CMD
$env:BERT_MODEL_DIR='D:\models\bert-base-chinese'     # PowerShell
export BERT_MODEL_DIR=/data/models/bert-base-chinese  # Linux / macOS
```

### 4.3 没有预训练模型时会怎样

- `tools/check_env.py` 明确报"未生成/未放置";
- 后端 `/models` 里 `bert` 显示为**未就绪**;
- 真的请求 `bert` 时**按顺序降级**到可用模型, 响应里带 `fallback_from: "bert"` 说明降级;
- 三个模型都不可用时才返回 503 + 业务码 `50002`。

**不会静默替换, 也不会让接口崩掉。**

## 五、装完先自检

```bash
# 1) 依赖 + 数据 + 模型产物三合一自检
python tools/check_env.py

# 只检查某个阶段
python tools/check_env.py --stage rf
python tools/check_env.py --stage backend

# 2) 数据集体检(格式 / 标签合法性 / 分布 / 共现)
python tools/check_dataset.py

# 3) 一键跑通所有阶段 + 端到端接口自测
python tools/verify_all_phases.py
python tools/verify_all_phases.py --api     # 只跑接口, 最快, 不需要 MySQL/Redis
python tools/verify_all_phases.py --fast    # 跳过需要加载模型的慢阶段
```

`check_env.py` 会自动列一张「模块 / pip 包名 / 属于哪个阶段 / 是否必需 / 安装状态」的表,
末尾直接给出缺什么、装哪些, 比如:

```
[警告] 必需依赖缺失, 对应阶段无法运行:
       pip install torch transformers
```

### 启动服务

```bash
python backend/main.py
# 页面:      http://127.0.0.1:8000/app
# 接口文档:  http://127.0.0.1:8000/docs
# 健康检查:  http://127.0.0.1:8000/api/v1/health   (免登录)
```

首次启动会自动创建管理员 `admin / admin123`(可被 `ADMIN_PASSWORD` 覆盖), 也可以直接在
页面注册普通账号。

## 六、按角色的最短路径

| 你的目标 | 需要装 | 需要起 | 需要模型 |
|---|---|---|---|
| 只想看页面/接口长什么样 | 服务层 6 个包 | 都不需要 | 不需要 |
| 跑对照实验(RF / FastText) | 服务层 + `02`/`03` 依赖 | 都不需要 | 仓库自带 |
| 跑 BERT 训练 | 服务层 + torch + transformers | 都不需要 | **自备 `bert-base-chinese`** |
| 完整体验(含落库/限流/黑名单) | 全部 | MySQL + Redis | 按需 |
| 答辩演示 | 服务层 + `02`/`03` | 不需要(降级即可) | 仓库自带 |

## 七、常见问题

### Q: `ModuleNotFoundError: No module named 'fasttext'`

Windows 上直接 `pip install fasttext` 多半要**本地编译**(依赖 Visual C++ 构建工具), 很容易失败。
本项目实测可用的装法是装预编译 wheel:

```bash
pip install fasttext-wheel
```

发行包叫 `fasttext-wheel`, 但 **import 的名字仍然是 `fasttext`**, 代码一行都不用改。
如果还是装不上, 去 [UCI Gohlke 页面](https://www.lfd.uci.edu/~gohlke/pythonlibs/#fasttext)
下对应 Python 版本的 `.whl`, 再 `pip install xxx.whl`。

> 顺带说明: `fasttext` 没有暴露 `__version__`, 所以 `python tools/check_env.py` 里它的
> 版本一栏显示为 `?` —— 这是正常的, 只要「状态」是「已安装」就没问题。

### Q: 报 `config` 模块串味 / 导入到别的项目的 config

`02-rf/`、`03-fasttext/`、`04-bert/` 各自都有一个叫 `config.py` 的文件。如果在**同一个
Python 进程**里先后 import 两个, 第二个会命中 `sys.modules` 缓存拿到第一个 —— 这是本项目
把每个阶段都放进独立子进程跑的原因(`tools/verify_all_phases.py` 就是这么做的)。

后端的 `backend/common/model_registry.py` 也为此做了隔离加载: 三个 config 会以
`_shopcare_02_rf_config` / `_shopcare_03_ft_config` / `_shopcare_04_bert_config`
三个互不相同的模块名注册, 可以安全地在同一个进程里共存。

**你自己写脚本时**: 不要 `import config`, 要么用 `importlib` 带唯一模块名加载, 要么起子进程。

### Q: 端口 8000 被占用

```bash
python backend/main.py --port 8001
```

或先查占用:

```powershell
netstat -ano | Select-String ':8000'
```

### Q: 限流太紧, 自测时被 429

把 `RATE_LIMIT_PER_MINUTE` 调大(默认 120/分钟/IP)。`/health`、`/static`、`/app`
这类静态与探活路径已经**豁免限流**, 不会影响页面加载。

### Q: 分类结果一直是"拒识"

两条路:

1. **看是不是真的该拒**: 演示语料外的口语化文本本来就容易拒识, 这是设计目标(不硬猜);
2. **还嫌太严**: 调低 `LABEL_THRESHOLD`(默认 0.5)。02/03 阶段训练时做过阈值搜索,
   最优点在 `0.3 / 0.6` 附近, 想复现训练期口径就把这两个值都设过去。

### Q: 首次请求很慢(约 7 秒)

随机森林模型是 joblib 反序列化的, 首次加载约 7 s(之后常驻内存)。FastText 只要 0.08 s。
这是**懒加载 + 进程内缓存**的预期代价, 不是卡死。

### Q: `/health` 报了配置告警

默认值(`JWT_SECRET=dev-secret-change-me`、`ADMIN_PASSWORD=admin123`)会触发告警,
这是**预期行为**, 提醒你别把默认值带上生产。改掉 `.env` 里这两项即可消除。

### Q: 没有显卡能跑吗?

能。全部三个阶段都有 CPU 路径, 配置里会自动选设备。BERT 训练在 CPU 上慢一些,
演示语料(4000 条)量级下大概几分钟一轮。
